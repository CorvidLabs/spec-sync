# Released SpecSync 6.2.0 refuses a change that holds a relayed approval, review or correction, with its 'written by a newer SpecSync' message, instead of rewriting it and dropping relayed_by: 6.3.0 records such a change at workflow version 3 (#1064, Leif's option (a))

## Goal

Released SpecSync 6.2.0 refuses a change that holds a relayed approval, review or correction, with its 'written by a newer SpecSync' message, instead of rewriting it and dropping relayed_by: 6.3.0 records such a change at workflow version 3 (#1064, Leif's option (a))

## Where it stands

- Implemented REQ-change-158: version-3 load, anchor and history rules; execution digest reads 3 as 2; approve and review raise before writing a relay; every state.json writer goes through relay_gated_record; v1 note; tests; compat script wired into CI and fledge; spec invariant 60, testing entry, change.3md z=52, docs, CHANGELOG
- Gated the reopen and reconcile-history state writers per t384's review; pinned approve's raise-first order with a test

## Decisions and why

- Authorization: Leif decided #1064 as option (a), his word 'A', relayed by hc t370 on 2026-11-11: 6.3.0 must stop released 6.2.0 from rewriting a change record that carries a relayed decision, rather than letting it silently drop relayed_by. The requirement wording goes to t370 for alignment and Leif runs the approve command; this agent does not approve it.
- rejected: option (b), accepting the limit and documenting it, because Leif chose (a)
- decided: gate only changes that hold a relayed decision, because raising every new change would lock 6.2.0 out of every repository 6.3.0 touches; measured: one v3 change already gates 6.2.0's change lifecycle repo-wide (research.md)
- decided: a relay on a workflow-v1 change is refused, because v1 cannot be raised to the gated version
- decided: a workflow-v1 change (which a --portable-5-0-1 pair requires) keeps version 1 and approve/review print a note that 6.2.0 and older can still drop its relay, because the portable pair exists so old binaries can read it and REQ-change-relayed-decision-001 keeps it; t370 chose 'fix 1+2' (coordinator, 2026-11-11) before Leif approved
- rejected: refusing relays on workflow-v1 changes (this agent's first delta) because it contradicted the portable line in the same delta and REQ-change-relayed-decision-001
- Native definition approval: Leif ran 'specsync change approve' himself (actor 0xLeif, 'definition approved (approved)'), relayed by hc t370 on 2026-11-11, after t370 aligned the wording and chose fix 1+2
