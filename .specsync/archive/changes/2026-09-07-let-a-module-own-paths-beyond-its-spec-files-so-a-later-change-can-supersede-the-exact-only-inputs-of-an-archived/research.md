# Research

- Ownership today: `acceptance_input_owners` returns `@exact:test` for `path_is_governed_test_or_fixture` and `@exact:delivery` for `path_is_recognized_delivery_metadata` BEFORE consulting any module; then each declared module owns its canonical spec and companions and the paths its spec's `files:` lists; owner corrections are appended; unowned production source is refused (or assigned `@exact:delivery` in legacy reconstruction) and anything else falls back to `@exact:delivery`. Exact owners are therefore always singletons and always win over `files:` for tests and delivery metadata.
- Succession today: `validate_supersedes_semantics` (draft `supersede` and acceptance) requires `entry.owners.contains(module)` on the PREDECESSOR's signed entry — the frozen label. `build_semantic_succession_evidence` separately requires the SUCCESSOR's own entry to carry the module. The walk (`validate_accepted_inputs_recursive`) treats any `@exact:` owner as exact-only: only the sequence-ledger path has a covering rule (`later_sequence_owner_covers_historical_input`); every other changed exact-only input is "requires an audited reopen".
- `[modules."name"]` already exists in `.specsync/config.toml` with `files` and `depends_on` (`ModuleDefinition`). `files` feeds coverage (`find_files_for_module`, `unspecced_modules`), so ownership needs its own key rather than a reuse of `files`. Config parsing is hand-rolled (`parse_toml_modules_nested`), typed by `validate_toml_field` in the checked parser, and written by `config_to_toml`, which skips a module carrying no data.
- Legacy manifest-less reconstruction (`reconstruct_legacy_acceptance_manifest`) runs `acceptance_manifest_legacy` against a detached checkout of the acceptance commit, so it reads that tree's configuration. No such tree carries `owns`; reconstruction is unaffected and needs no gating.
- `Tests/AlgorandTests` appears in manifests as `kind: non_file` with `@exact:test` because an `affected_paths` entry without a trailing slash is an extra candidate captured by `capture_working_candidate`. A directory matches `path_matches_scope` against itself, so it takes configured ownership like a file and needs succession only when it changes (deletion → `missing`), under the same rule.
- Three `ModuleDefinition` struct literals in `validator.rs` and `generator.rs` tests gain the field; those files change without any contract change, so they are covered by a separate `--no-spec-change` workspace rather than by inventing deltas for `validator` and `generator`.
- swift-algorand reproduction: PR #20 carved `Package.swift` and the DocC pages out of its scope because they could not be superseded; the 14 legacy XCTest files and the deprecated trapping APIs they exercise are frozen for the same reason; `feat/docc-gating` @ adeeeec holds the verified but unlandable `Package.swift` change.
