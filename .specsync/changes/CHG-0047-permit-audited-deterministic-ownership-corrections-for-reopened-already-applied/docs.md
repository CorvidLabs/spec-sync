# Docs

Document `change correct-owner` beside reopen and accepted-metadata correction. Explain that it is
for a historical input already inside the change's delivery scope whose current canonical owner
was omitted from the original affected-spec list. It is not a way to add delivery paths, alter
requirements, edit semantic deltas, or bypass a successor change.

The workflow example must show: audited reopen, exact owner correction with actor and reason,
definition reapproval, fresh verification, and closing reacceptance. Error guidance must distinguish
missing manifest ownership from a true semantic rescope.
