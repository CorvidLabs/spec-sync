# Testing

## Evidence policy

Every issue facet begins with a failing characterization against the pre-fix behavior. A test may
be converted into its passing regression only after the implementation demonstrates the failure.
Unit tests prove parser and resolver semantics; integration tests prove CLI output and exact exit
codes; MCP tests prove the same semantics remain inside its retained root authority; the private
`CorvidLabs/spec-sync-sandbox` repository proves behavior against a separately versioned consumer.

No result is accepted from only one renderer or one cache state. Text and JSON are mandatory for
all command outcomes; Mermaid and DOT are additionally mandatory for dependency-graph gates.

## Checked frontmatter matrix

Focused parser/type tests live in `src/parser.rs` and `src/types.rs`.

| Case | Expected result |
|------|-----------------|
| Valid block-list and flow-list frontmatter | Identical typed values and dependency identities |
| One or repeated leading BOM; CRLF input | Existing compatibility preserved |
| Duplicate known key such as a second `status` | `DuplicateKey`; neither value silently wins |
| Duplicate unknown extension key | `DuplicateKey`; extension cannot hide a second value |
| Valid unique unknown extension fields | Accepted and ignored by the canonical model |
| `depends_on: alpha` or `depends_on: {a: b}` | Field-specific `InvalidShape` |
| Unterminated array/quote, invalid indentation/tab, colon-less garbage | Syntax diagnostic with best available line |
| `implements`/`tracks` wrong shape or malformed member | Typed field diagnostic; no dropped member |
| Valid `implements`/`tracks` issue-number lists | Retained as typed metadata; no dependency graph node, edge, count, cycle, Mermaid, or DOT relationship |
| Numeric/string supported version | Accepted and normalized to the public version representation |
| Boolean, map, list, or non-version text in `version` | `InvalidType` or `InvalidValue` |
| Missing opening/closing delimiter | `MissingDelimiters`; validator reports the exact frontmatter failure |

Regression assertions include the #436 bypass where a hidden second `status: draft` must not
disable active-spec validation and the #419 flow-list form generated by SpecSync must produce real
edges.

## Dependency parsing and confinement matrix

Unit and integration fixtures exercise one table of raw values through check, deps, resolve,
scoring, and MCP. Each consumer must preserve the offending raw value and agree on the core error
kind.

| Input or filesystem state | Expected result |
|---------------------------|-----------------|
| Bare `alpha` with canonical spec | Resolves exactly to `specs/alpha/alpha.spec.md` |
| Bare module with registry custom path | Registry mapping wins and remains confined |
| Explicit `specs/alpha/alpha.spec.md` | Resolves as a local spec path |
| Valid `owner/repository@alpha` | Remote reference with validated repository/module |
| Empty, `repo@`, `/@`, multiple/empty remote components | Malformed error containing original input |
| POSIX absolute, `../`, `./`, repeated parent, backslash path | Rejected before filesystem probing |
| Windows drive absolute/relative, UNC, extended path, mixed separators | Rejected identically on Unix and Windows |
| In-root symlink/junction whose target escapes | `EscapesProjectRoot`; outside bytes are never read |
| Missing leaf below an escaping existing ancestor | Rejected as an escape, not merely reported missing |
| Equivalent repeated declaration | One normalized identity, one graph edge, original order retained |
| Canonical path with mismatched `module:` | Identity error |
| Registry-mapped custom path with matching registry key | Accepted despite non-conventional directory name |

Windows runtime CI covers drive-relative paths, UNC/extended prefixes, backslashes, and junction
escapes. Unix CI covers absolute paths and symlink escapes. Cross-platform fixtures assert
diagnostic parity rather than platform-specific host-path text.

## Registry and transport matrix

Registry unit tests live in `src/registry.rs`; shared GitHub transport tests live in
`src/github.rs`; command integration lives in `tests/integration/config.rs` and
`tests/integration/commands.rs`.

| Case | Expected result |
|------|-----------------|
| Canonical `[registry]` + `[specs]` | Parsed with deterministic mappings |
| Documented `[[modules]]` records | Same effective mappings as canonical form |
| Conflicting/duplicate mapping across either shape | Hard parse/semantic error |
| `name = {{{` or other malformed TOML | `failed to parse local registry <path> while resolving <module>`; no fallback |
| Valid empty 5.0.1 stub | Treated as absent and conventional resolution remains available |
| Invalid empty-looking TOML | Not treated as inert |
| Unsafe registry path | Rejected before local read, cache access, or network fetch |
| Generated registry with quoted/special TOML content | Re-parses exactly and remains `[specs]` |
| Primary `.specsync/registry.toml` returns 200 | Legacy path is never requested |
| Primary returns 404, legacy returns 200 | Legacy fallback succeeds |
| Primary returns 401, 403, timeout, malformed body, or transport error | No fallback; inconclusive failure with the original category preserved |
| Blackhole request expires under the invocation deadline | `timeout` in text/JSON/cache parity; never mislabeled `connection_refused` |
| `GITHUB_TOKEN` set/unset | Header present only when set; token absent from all output/cache artifacts |
| Oversized registry/spec response | Bounded failure before parse/cache |
| Several blackhole repositories | One bounded invocation deadline, not `N × 10s` sequential delay |

Private-repository coverage uses a disposable token in CI secrets and asserts only header behavior
and successful access; no token value is recorded as lifecycle evidence.

## Command and structured-output matrix

End-to-end tests live in `tests/integration/commands.rs`, with config/registry fixtures in
`tests/integration/config.rs` and MCP fixtures in `tests/integration/mcp.rs`.

| Command case | Exit | Required output |
|--------------|------|-----------------|
| All local dependencies valid | `0` | `valid: true`, `gate_passed: true` in JSON |
| Missing local dependency | `1` | Same failing raw ref in text and JSON, with or without `--strict` |
| Malformed or escaping dependency | `1` | Same core diagnostic in check/deps/resolve/MCP |
| `deps --require-coverage 100` with uncovered source | `1` | Coverage details and failed gate in every output mode |
| `deps --require-coverage 101` | `2` | Usage diagnostic; no success report |
| Coverage gate with zero sources or malformed manifest discovery | `1` | Inconclusive, never vacuous 100% success |
| Dependency warning without strict mode | `0` | Advisory warning; `valid` and `gate_passed` remain explicit |
| Dependency warning with strict mode | `1` | Warning promoted without corrupting JSON |
| Mermaid/DOT with any validation or coverage failure | `1` | Deterministic diagram plus nonzero gate; no duplicate edge |
| `resolve --remote` registry fetch failure | `1` | Per-repository inconclusive outcome; no false checkmark |
| `resolve --remote` bounded deadline expiry | `1` | Timeout category in text and JSON; never “Connection refused” |
| Remote module absent or spec unavailable/unparseable | `1` | Failing per-reference outcome |
| `resolve --verify` with zero successful registries | `1` | Must not print “no drift detected” |
| Non-bidirectional remote reference, non-strict/strict | `0`/`1` | Advisory then promoted finding |
| Any failing `--format json` invocation | Per row | One parseable JSON document; no ANSI/human preamble |
| Unsupported CLI use | `2` | Clap/usage result, distinct from findings |

JSON assertions validate fields and types, not only substring presence. At minimum the dependency
and resolve reports expose `valid`, `gate_passed`, diagnostics, requested gates, coverage where
applicable, and every raw offending reference. Text assertions remove the doubled “Local Local
dependencies” heading and forbid success language after an inconclusive remote result.

## Warm/cold and MCP parity

- Run checked validation and remote resolution once with empty caches and once with populated
  versioned caches; reports, exit codes, dependency identities, and diagnostics must match except
  for an explicit cache-provenance field.
- Corrupt, stale, or schema-version-mismatched cache entries must be ignored or fail closed; they
  may not turn an invalid cold run into a valid warm run.
- MCP resources, graph output, check, score, and coverage use the same fixture table. Malformed or
  escaping inputs return tool/resource errors with `valid: false`/`gate_passed: false` and never
  read outside the retained server root.
- MCP integration occurs only after the #414 root-confinement work is present. Re-run traversal,
  symlink, Windows junction, argument-shape, notification, and bounded-I/O regressions to prove
  the parser migration did not weaken that boundary.
