Cargo.toml, the specsync Cargo.lock entry, and the self-built CI Action consumer and Trust candidate inputs move to 6.1.2. Documentation examples pin `@v6.1.2` with `version: '6.1.2'` for use after publication. Archive-gate examples keep `@main` until 6.1.2 is published, because `@v6.1.1` ignores those inputs. The Action omitted-input default stays published 6.1.1 (`PUBLISHED_ACTION_DEFAULT`). Existing immutable tags and floating `v6` are untouched. Rust's declared minimum stays 1.89 and Linux/macOS remain the supported release platforms.

## What the release workflow does

- Pushing an annotated `v6.1.2-rc.N` tag runs `release.yml` in qualify mode: resolve, validate (ancestor of `origin/main`, Cargo version equals tag version), the `release-candidate` lane on Ubuntu and macOS, then a `SpecSync release candidate` check run. No release and no binaries.
- Dispatching `release.yml` with `rc_tag` promotes: mints annotated `v6.1.2` at the candidate SHA, builds five binaries (Linux x86_64, x86_64 musl, aarch64; macOS x86_64, aarch64) with `.sha256` sidecars, and creates a non-prerelease GitHub release, which moves `releases/latest`.
- It does not publish to crates.io, does not touch Homebrew and does not move floating `v6`. Those are manual steps in [RELEASING.md](../RELEASING.md).

## Superseded candidate

`v6.1.2-rc.1` (tag object `520f1cc0`, commit `8873c08d`) failed qualification in release run 41340279221. Ubuntu passed; the macOS job ran on `macos-14` and GitHub failed it before any step during the scheduled brownout of 2026-11-01 14:00 UTC to 2026-11-02 00:00 UTC, ahead of that image's retirement on 2026-11-02 (actions/runner-images#13518). A tag push runs the workflow from the tagged commit, so rc.1 cannot requalify. It is left as is and superseded by `v6.1.2-rc.2`.
