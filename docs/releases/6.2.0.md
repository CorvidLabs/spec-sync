Mixed-version writers: 6.1.x binaries do not know the `approved_delta_bases` and `send_backs` approval-ledger fields. Raise every lifecycle writer and CI pin to 6.2.0 together after publication.

## What the release workflow does

- Pushing an annotated `v6.2.0-rc.N` tag runs `release.yml` in qualify mode: resolve, validate (ancestor of `origin/main`, Cargo version equals tag version), the `release-candidate` lane on Ubuntu and macOS, then a `SpecSync release candidate` check run. No release and no binaries.
- Dispatching `release.yml` with `rc_tag` promotes: mints annotated `v6.2.0` at the candidate SHA, builds five binaries (Linux x86_64, x86_64 musl, aarch64; macOS x86_64, aarch64) with `.sha256` sidecars, and creates a non-prerelease GitHub release, which moves `releases/latest`.
- It does not publish to crates.io, does not touch Homebrew and does not move floating `v6`. Those are manual steps in [RELEASING.md](../RELEASING.md).
