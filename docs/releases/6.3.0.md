# SpecSync 6.3.0 preparation

Status: **prepared, not tagged.** Do not merge until Leif says go. No RC tag, release, crates.io
publish or Homebrew change happens from this PR. Leif's decision (coordinator chat, 2026-11-12,
relayed by the coordinator agent t370): "yes chough 0.6.0 ships with spec-sync 6.3.0". This file is
the release handoff record.

6.3.0 is a minor release. Since 6.2.0, `main` adds commands and options:

- `specsync doctor`;
- `change retire`;
- `change repair-relays`;
- relayed decisions on `change approve` and `change review`;
- `--timeout` on the read commands;
- the unrun-verification-commands note;
- a static `specsync-linux-aarch64-musl` download.

Under SemVer that is 6.3.0, not 6.2.1.

## Upgrade notes

- **Relayed decisions need 6.3.0 everywhere change commands run.** A change that holds a relayed
  decision is recorded at workflow version 3. SpecSync 6.2.0 and older refuse such a change with
  "was written by a newer SpecSync" instead of rewriting it and dropping `relayed_by` (#1064,
  REQ-change-158). Once a repository records one relayed decision, every machine that runs change
  commands there needs SpecSync 6.3.0 or later. Check-only uses, such as the Action and Trust pinned
  at 6.2.0, keep working. Upgrade every install before recording a relayed decision. Chough 0.6.0
  records relayed reviews through `chough change ship`.
- Relays on legacy workflow-v1 (portable 5.0.1) changes are not gated, and approve and review say
  so.
- The Linux glibc downloads now start on glibc 2.35 or newer (Ubuntu 22.04, Debian 12). Through
  6.2.0 they needed glibc 2.39. The static musl downloads cover anything older (#882).
- Mixed-version writers: 6.2.0 does not keep fields a newer SpecSync writes, such as
  `cancelled_review_attempts`; from 6.3.0 on, a rewrite keeps unknown fields (#1044). Raise every
  lifecycle writer and CI pin to 6.3.0 together after publication.
- Security: `cap-primitives` 4.0.3 fixes RUSTSEC-2026-0482 (CVSS 9), which 6.2.0 shipped (#1054).

## The release lane

The lane is `release.yml` and `rc-assets.yml`, unchanged since 6.2.0 apart from the two fixes
below. See [RELEASING.md](../RELEASING.md).

- An annotated `v6.3.0-rc.N` tag push qualifies the candidate on Ubuntu and macOS. It creates no
  release and no binaries.
- Promotion (`workflow_dispatch` with `rc_tag`) mints immutable `v6.3.0`. It then builds six
  archives, each Linux one checked by `linux-baseline.py`, and publishes a non-prerelease release,
  which moves `releases/latest`.
- Since 6.2.0, `release.yml` `build` and `rc-assets.yml` `build` install musl-tools through
  `.github/scripts/install-musl-tools.sh`, which retries and falls back to other Ubuntu mirrors, as
  CI does (#1066).
- No release or RC job runs augur or a CorvidLabs/trust gate, so none needs the ubuntu-24.04 pin
  that `trust.yml`'s `trust` job carries for CorvidLabs/augur#59 (#1065).
- This is the first release with the sixth archive, `specsync-linux-aarch64-musl`: twelve assets
  with the `.sha256` sidecars.
