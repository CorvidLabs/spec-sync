Status: **published 2026-11-21** from `v6.4.1-rc.1` (`3f0985e8`) as GitHub release `v6.4.1`
(Latest, twelve assets). crates.io serves 6.4.1 and the Homebrew tap carries it. Leif gave the go

## Upgrade notes

6.4.1 closes the low-severity items left after GHSA-7q5v-8jcc-rx54 (#1137). `CHANGELOG.md`
`### Security` under `[6.4.1]` lists each part. These change what you see:

- **A transaction journal SpecSync 6.4.0 wrote is not replayed.** The journal now lives in your
  user state folder (`$XDG_STATE_HOME`, else `~/Library/Application Support` on macOS,
  `%LOCALAPPDATA%` on Windows or `~/.local/state`) and records the project it belongs to. One
  6.4.0 left behind records no project, so lifecycle commands stop with its path until you check
  the files it lists and delete it.
- **On Unix, SpecSync's own state folders are private (0700).** A folder another user owns, or that
  its group or others can write, is refused. Folders SpecSync 6.4.0 made under a umask of 002
  (Fedora, RHEL, and Debian or Ubuntu with per-user groups) are refused until you run the
  `chmod -R go-w <cache folder>/specsync` the message names, once.
- **A project folder that would lie inside the project is refused.**
- **Record folders committed as a link out are refused**, with the folder named:
  `.specsync/archive/changes`, a change's `deltas`, and a spec's `history/`.
- **`hooks`** manages a hooks folder outside the work tree and Git directory only when your own
  global or system Git config names it. It no longer writes `pre-commit` into an existing folder
  that a repository's own config names.
- **`rehash` exits 1** rather than writing a hash cache larger than the bound SpecSync reads.
  `check` warns once and keeps the cache already there.
- The main Action wrapper's omitted-input default is the published 6.4.0 binary (#1136). An
  immutable `@v6.4.1` tag, once cut, embeds the default of the commit it is cut from, so pass
  `version: '6.4.1'` with it.

## The release lane

`release.yml` and `rc-assets.yml` are unchanged since 6.4.0. See [RELEASING.md](../RELEASING.md).

- An annotated `v6.4.1-rc.N` tag push qualifies the candidate on Ubuntu and macOS. It creates no
  release and no binaries.
- Promotion (`workflow_dispatch` with `rc_tag`) mints immutable `v6.4.1`. It then builds six
  archives, each Linux one checked by `linux-baseline.py`, and publishes a non-prerelease release,
  which moves `releases/latest`: twelve assets with the `.sha256` sidecars.
