# SpecSync 6.4.2 preparation

This patch is in preparation. The changes below are on main at `4970833e`. Reconcile them with [the changelog](../../CHANGELOG.md) on the final main revision and set the release date before creating the candidate tag.

## Changes since 6.4.1

- Change verification and shipping detect a canonical requirement that disappears from a branch without an approved removal. The diagnostic identifies the missing requirement and the Git revision from which it can be restored. [#1108](https://github.com/CorvidLabs/spec-sync/pull/1108)
- Verification accepts an ignored path beneath a source directory when the configured source walk excludes that directory. Validation continues to reject paths that would hide source inputs. [#1152](https://github.com/CorvidLabs/spec-sync/pull/1152)
- The watch-mode integration tests wait for the run footer before checking output, so they evaluate diagnostics emitted after the verdict. [#1153](https://github.com/CorvidLabs/spec-sync/pull/1153)
- The lockfile selects `cookie` 0.18.3 for RUSTSEC-2026-0594. [#1148](https://github.com/CorvidLabs/spec-sync/pull/1148)
- Scoped verification writes its evidence and the change state together. Rechecking repairs a stale Markdown summary and preserves the maintainer’s notes when the frontmatter is intact. [#1147](https://github.com/CorvidLabs/spec-sync/pull/1147)
- Strict change audit identifies a delta targeting a frozen Change Log and names the affected change. [#1145](https://github.com/CorvidLabs/spec-sync/pull/1145)
- The lockfile selects `url` 2.5.9 and `form_urlencoded` 1.2.3 for RUSTSEC-2026-0592. [#1146](https://github.com/CorvidLabs/spec-sync/pull/1146)
- The README and site include corrected 6.4 guidance. The main Action selects the published 6.4.1 binary by default. [#1141](https://github.com/CorvidLabs/spec-sync/pull/1141) · [#1142](https://github.com/CorvidLabs/spec-sync/pull/1142)

## Action consumers

CI and Trust test their locally built 6.4.2 binary. Until stable publication, use the published `@v6.4.1` wrapper with `version: '6.4.1'`. After publication, select `@v6.4.2` and pass `version: '6.4.2'` explicitly. A wrapper cut from this preparation still selects the published 6.4.1 binary when the version input is omitted.

## Release handoff

Archive the release change, merge the green preparation PR, and qualify an annotated candidate on the chosen main SHA. Confirm successful Ubuntu and macOS qualification before promoting it. Verify the six published archives and their six checksum files. Record the tag, SHA and workflow run in the release receipt. [Release runbook](../RELEASING.md)

A subsequent update advances the default binary and the floating `v6` Action ref after the published assets pass consumer checks. The Cargo registry and Homebrew have separate publication steps in the runbook.
