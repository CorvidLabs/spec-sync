# SpecSync 6.4.2

SpecSync 6.4.2 was published on 2026-11-24 from `v6.4.2-rc.2` (`a275ab44`) as GitHub release [`v6.4.2`](https://github.com/CorvidLabs/spec-sync/releases/tag/v6.4.2), which is Latest and has twelve assets. crates.io serves 6.4.2, and the Homebrew tap carries it (CorvidLabs/homebrew-tap#45). The changes below are the 6.4.2 section of [the changelog](../../CHANGELOG.md).

## Changes since 6.4.1

- After the last change is archived, `change audit` and `check --strict` both report a canonical requirement that a branch lost without an approved removal, and name the commit it can be restored from. A branch that disables or deletes its SDD policy is still compared while its comparison base has SDD enabled. [#1149](https://github.com/CorvidLabs/spec-sync/pull/1149)
- `change adopt --dry-run` refuses what adoption would refuse, including an unsupported source and Markdown that is not UTF-8 or is over the read limit. `check --fix --json` prints one JSON document on stdout, and a failed repair is reported in every output format. A merge-driver union keeps a quoted date quoted. [#1151](https://github.com/CorvidLabs/spec-sync/pull/1151)
- One change whose records fail validation no longer decides another change's terminal evidence in status, list or ship-status. `change correct` still validates the whole roster before it writes. [#1114](https://github.com/CorvidLabs/spec-sync/pull/1114)
- An accepted change stays current while a later change still in flight declares the input they share, and status and audit name the covering change. The warning stays when that change is accepted without declaring succession. When two accepted changes block each other's archival over one input, each refusal names the other. [#1132](https://github.com/CorvidLabs/spec-sync/pull/1132)
- The lost-requirements check reads only the requirements files that were canonical at the commit it compares with. `change audit` reports a branch's loss beside a change's own validation error, and a requirements file or directory that cannot be read is named instead of its requirements being reported lost. [#1134](https://github.com/CorvidLabs/spec-sync/pull/1134)
- History checks honor configured safe-directory settings. Shallow clones receive a working fetch command before change creation can write files, and partial clones get a recovery command for missing Git objects. [#1122](https://github.com/CorvidLabs/spec-sync/pull/1122)
- When an accepted change cannot reopen, ship guidance identifies the blocker and reports the available recovery action. [#1154](https://github.com/CorvidLabs/spec-sync/pull/1154)
- The CLI now checks upstream branch visibility when reporting archived or unavailable archives, and preserves native path bytes when reopening a renamed archive. [#1155](https://github.com/CorvidLabs/spec-sync/pull/1155)
- Archive recovery restores exactly the named package, including paths with wildcards or control characters. Baseline checks also work in project directories whose names resemble Git path patterns. [#1150](https://github.com/CorvidLabs/spec-sync/pull/1150)
- A requirement delta now updates or removes the canonical requirement when an earlier fenced example quotes the same ID. Replaying the change preserves the example. [#1144](https://github.com/CorvidLabs/spec-sync/pull/1144)
- Finalization, shipping and archival require committed approval evidence. If the approval ledger was edited, the CLI identifies the affected file and the Git operation that can restore it. [#1120](https://github.com/CorvidLabs/spec-sync/pull/1120)
- When main and an approved change edit different words in the same requirement, `change check` proposes the combined wording and asks for a new approval. Overlapping edits leave the proposal untouched. [#1089](https://github.com/CorvidLabs/spec-sync/pull/1089)
- Change verification and shipping detect a canonical requirement that disappears from a branch without an approved removal. The diagnostic identifies the missing requirement and the Git revision from which it can be restored. [#1108](https://github.com/CorvidLabs/spec-sync/pull/1108)
- Verification accepts an ignored path beneath a source directory when the configured source walk excludes that directory. Validation continues to reject paths that would hide source inputs. [#1152](https://github.com/CorvidLabs/spec-sync/pull/1152)
- The watch-mode integration tests wait for the run footer before checking output, so they evaluate diagnostics emitted after the verdict. [#1153](https://github.com/CorvidLabs/spec-sync/pull/1153)
- The lockfile selects `cookie` 0.18.3 for RUSTSEC-2026-0594. [#1148](https://github.com/CorvidLabs/spec-sync/pull/1148)
- Scoped verification writes its evidence and the change state together. Rechecking repairs a stale Markdown summary and preserves the maintainer’s notes when the frontmatter is intact. [#1147](https://github.com/CorvidLabs/spec-sync/pull/1147)
- Strict change audit identifies a delta targeting a frozen Change Log and names the affected change. [#1145](https://github.com/CorvidLabs/spec-sync/pull/1145)
- The lockfile selects `url` 2.5.9 and `form_urlencoded` 1.2.3 for RUSTSEC-2026-0592. [#1146](https://github.com/CorvidLabs/spec-sync/pull/1146)
- The README and site include corrected 6.4 guidance. The main Action selects the published 6.4.1 binary by default. [#1141](https://github.com/CorvidLabs/spec-sync/pull/1141) · [#1142](https://github.com/CorvidLabs/spec-sync/pull/1142)

## Action consumers

Select `@v6.4.2` and pass `version: '6.4.2'` explicitly: the wrapper at that immutable tag still selects the published 6.4.1 binary when the version input is omitted. The main wrapper selects 6.4.2 by default from the update that records this publication. CI and Trust test their locally built binary.

## Release handoff

`v6.4.2-rc.1` qualified on Ubuntu. Its macOS run passed all 4,176 tests and was then cancelled at the 75-minute `qualify` limit during the release build, so it cannot be promoted. From `v6.4.2-rc.2` the limit is 120 minutes. That is a stopgap: the lane needs about 84 minutes on macOS, and bringing every test lane under 30 minutes is tracked in [#1161](https://github.com/CorvidLabs/spec-sync/issues/1161).

The release contract tests use disposable repositories with isolated Git configuration. Maintainers who sign tags by default can run the tests with their usual settings. [#1110](https://github.com/CorvidLabs/spec-sync/issues/1110)

`v6.4.2-rc.2` (`a275ab44`) qualified on Ubuntu in 22m31s and on macOS in 78m32s (`release.yml` run 45472594205). Both platform evidence records and the `SpecSync release candidate` check run name that tag, version 6.4.2 and that commit. A dry run (run 45489088237) created nothing. Promotion (run 45489261983) created the annotated `v6.4.2` tag at the candidate, built the six archives and published the release. [Release runbook](../RELEASING.md)

After publication, `v6.4.2` peels to `a275ab44`, the release is Latest with its twelve assets, and all six archives match their checksum files. The published `specsync-macos-aarch64` binary reports `specsync 6.4.2`, carries the candidate's source fingerprint, passes this repository's strict check and archive audit, and runs the lifecycle example. crates.io serves 6.4.2, published from the tagged tree with the checksum of the crate built there. The Homebrew formula takes its four checksums from the release's checksum files; installed from the tap, `specsync` is the published macOS arm64 binary byte for byte.

Consumer pins did not move: podo-android pins `v6.0.0`, raven pins the `v6.2.0` commit with `version: "6.2.0"`, and podo-web inherits its pin through a pinned Trust commit. None follows `latest`, so promotion changed nothing for them.

The update that records this publication advances the main wrapper's default binary to 6.4.2. The floating `v6` Action ref moves separately, after that wrapper commit's consumer checks.
