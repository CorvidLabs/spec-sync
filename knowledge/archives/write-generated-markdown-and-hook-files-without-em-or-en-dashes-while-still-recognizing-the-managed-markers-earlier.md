## Acceptance criteria

- After `specsync change finalize`, the archived `lesson-bundle.md` opens with `# Lesson bundle: <id>`, and every U+2013 or U+2014 it contains comes from user-supplied record text that the bundle copies verbatim: the change's title, acceptance criteria, affected specs and paths, recorded verification command strings, and the bodies of its context.md, design.md and testing.md. The bundle's own fixed text and heading add neither character.
- `specsync init`, `specsync migrate` (3.x to v4 layout), `specsync hooks install` for every target (CLAUDE.md, .cursorrules, .github/copilot-instructions.md, AGENTS.md, the Git pre-commit hook, .claude/settings.json), `specsync agents install` for every tool, and `specsync compact` summary rows write no U+2013 or U+2014.
- The managed instruction block begins with `<!-- specsync:hook:begin (managed by `specsync hooks`; do not edit inside) -->` and still ends with the unchanged `<!-- specsync:hook:end -->`. `specsync hooks uninstall` removes a block whose begin line is the 6.1.1 form exactly as it removes the new form, preserving content before and after it; `hooks install` and `hooks status` keep treating either form as installed.
- `specsync hooks uninstall --precommit` still removes a project-keyed managed block whose body 6.1.1 wrote, found by its unchanged markers. Recognition of unmarked legacy hooks (an appended block after `# --- spec-sync pre-commit hook ---`, or a whole-file hook) keeps comparing against the current hook body, as today; no frozen copy of an older body is added.
- A compaction summary row is written as `  <first> to <last>   -   Compacted: N entries <!-- specsync:compact:v1 -->  `. A summary row in the 6.1.1 form (a U+2014 range separator surrounded by spaces, and U+2014 placeholder cells) is still recognized as the prior summary: a no-excess re-run leaves the file byte-for-byte unchanged, and a run that compacts more entries folds its count and range start into one new-form row.
- `AGENT_ARTIFACT_TEMPLATE_VERSION` advances to 7, so `specsync agents install` refreshes create-spec command files whose bytes still match their recorded digest, and the repository's own installed copies and `.specsync/agent-artifacts.json` are regenerated from the built binary.
- A regression test drives every writer in the second criterion (init, migrate, hooks install, agents install and compact) through the built binary in a disposable repository and fails if any file it writes, other than user-supplied input, contains U+2013 or U+2014. It fails on origin/main a80748ff and passes with the fix. The lesson bundle is covered by an in-process unit test of `write_lesson_bundle`, because a binary-driven finalize needs a fully approved and reviewed change.
- Unchanged: terminal, JSON and stdout Markdown output (including `--format markdown` reports, `specsync comment` bodies and issue verification text); the `Spec-Sync Integration` and `Spec-Sync Rules` install-detection markers; the end marker and pre-commit project-keyed markers; frozen archives under `.specsync/archive/`; existing installed blocks and compacted rows, which are not rewritten until the user reinstalls or compaction next folds them.
