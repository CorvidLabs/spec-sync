A monorepo with a TypeScript frontend, a Python ML service, and a Rust binary can share a single spec format. `specsync` detects each language automatically and applies the right validation rules per crate or package.

## 1. Check the whole repo at once

```bash
specsync check
```

`specsync` walks the repo, discovers source trees from language manifests, and validates every mapped spec in a single pass.

## 2. How language detection works

`--explain` is not a language-detection flag. `specsync score --explain` prints a quality-score breakdown. `specsync check --explain` (when used) prints the same score breakdown; it does not report which language a spec was checked against.

There is no `[[language_overrides]]` table in `.specsync/config.toml`. Manifest discovery and file extensions select the language:

- Rust: `Cargo.toml`, then `.rs` files
- Python: `pyproject.toml`, then `.py` files
- TypeScript/JavaScript: `package.json`, then `.ts` / `.tsx` / `.js` / `.jsx` files

If a tree is not discovered, set `source_dirs` in `.specsync/config.toml` or list the files in the spec `files:` frontmatter.

## 3. Add a polyglot ignore for shared types

A shared `types/` directory that's imported by all three services doesn't need a spec. Exclude it with the real config keys:

```toml
# .specsync/config.toml
exclude_dirs = ["types"]
exclude_patterns = ["**/*.test.ts", "**/*.test.py", "**/*.test.rs"]
```

## 4. Define cross-language references

The TypeScript API spec references a type owned by the Rust server. Use a cross-project reference:

```markdown
<!-- specs/web/api.spec.md -->

## Returns

The endpoint returns a [`HandlerResponse`](crates/server/specs/handlers.spec.md#handlerresponse)
serialized as JSON.
```

`specsync deps` validates declared cross-module relationships; `specsync check` fails if a documented export such as `HandlerResponse` disappears from its Rust source.

## 5. Generate missing entries per language

For undocumented exports across all three languages in one shot:

```bash
specsync check --fix
```

The deterministic fixer adds language-aware review rows for newly discovered exports. Complete their descriptions yourself or with your configured coding agent, then review before committing.

## 6. Wire the CI gate

```yaml
# .github/workflows/spec-sync.yml
name: spec-sync
on: [pull_request]
jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: CorvidLabs/spec-sync@v6.0.0
        with:
          version: '6.0.0'
          strict: true
```

Pin both the Action ref and the binary version. The `@v6.0.0` Action tag still defaults omitted `version` to `6.0.0-rc.14`. The Action runs `specsync check --force --strict` against every PR. Drift in any of the three languages blocks the merge.

## 7. Add the VS Code extension

Install [spec-sync for VS Code](https://github.com/CorvidLabs/spec-sync/tree/main/vscode-extension) on every developer machine. Spec drift surfaces inline in the editor: no `cargo install`, no terminal, no excuse.

```
# in any of the spec files, undocumented exports appear with a yellow squiggle
# and a quick-fix offers "Generate spec entry"
```

Now you have one spec format, three languages, one CI gate, and an editor that nudges before drift ever lands in a PR.
